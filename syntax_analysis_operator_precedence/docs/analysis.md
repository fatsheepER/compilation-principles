# 实验 3：算符优先分析实现方法说明

本文档用于明确实验 3 中应实现的具体语法分析方法。实验重点是：根据给定表达式文法，求 `FirstVT` / `LastVT` 集，构造算符优先关系表，并用“移进—归约”的算符优先分析过程判断输入表达式是否合法。

本文档不要求实现优先函数方法，因此不讨论 Floyd 优先函数转换。

---

## 1. 实验目标

实现一个基于算符优先分析法的表达式语法分析程序，完成以下任务：

1. 根据给定文法求出每个非终结符的 `FirstVT` 集和 `LastVT` 集；
2. 根据 `FirstVT` / `LastVT` 集构造算符优先关系表；
3. 对输入表达式进行算符优先分析；
4. 判断表达式是否符合文法；
5. 输出分析过程，尤其是移进和归约过程。

---

## 2. 使用的表达式文法

实验中使用的基础文法为：

```text
E → E + T | T
T → T * F | F
F → ( E ) | i
```

其中：

```text
非终结符 VN = { E, T, F }
终结符 VT = { +, *, (, ), i }
```

为了便于分析，需要额外引入输入结束符 `#`：

```text
VT' = { +, *, (, ), i, # }
```

`#` 用作栈底符号和输入结束符。

---

## 3. 算符优先文法的基本约束

算符优先分析只处理终结符之间的优先关系。

对于文法中的任意两个相邻终结符，或者隔着一个非终结符相邻的终结符，需要确定它们之间的优先关系。

优先关系有三种：

```text
a < b   表示 a 的优先级低于 b，分析时通常移进 b
a = b   表示 a 与 b 同级，常用于括号、相邻终结符结构等
a > b   表示 a 的优先级高于 b，分析时通常进行归约
```

注意：

```text
a < b 不能推出 b > a
a = b 不能推出 b = a
a > b 不能推出 b < a
```

算符优先关系是有方向的，必须分别根据文法规则推导得到。

---

## 4. FirstVT 集

### 4.1 定义

`FirstVT(P)` 表示：从非终结符 `P` 推导出的句型中，可能出现在最左边的终结符集合。

也就是说，如果从 `P` 出发推导出的某个句型最左侧第一个终结符是 `a`，那么：

```text
a ∈ FirstVT(P)
```

这里的 `VT` 表示 Vocabulary Terminal，即终结符集合。

### 4.2 求 FirstVT(P) 的规则

对每个非终结符 `P`，按以下规则求 `FirstVT(P)`：

#### 规则 1：直接出现终结符

如果有产生式：

```text
P → a ...
```

或者：

```text
P → Q a ...
```

其中 `a` 是终结符，`Q` 是非终结符，则：

```text
a ∈ FirstVT(P)
```

也就是说：

- 如果产生式右部第一个符号就是终结符 `a`，则加入；
- 如果产生式右部第一个符号是非终结符 `Q`，第二个符号是终结符 `a`，也加入。

#### 规则 2：传递加入

如果有产生式：

```text
P → Q ...
```

则：

```text
FirstVT(Q) ⊆ FirstVT(P)
```

即 `Q` 能够首先推出的终结符，也可能成为 `P` 首先推出的终结符。

#### 规则 3：反复迭代到不再变化

重复应用规则 1 和规则 2，直到所有非终结符的 `FirstVT` 集不再增加新的终结符为止。

---

## 5. LastVT 集

### 5.1 定义

`LastVT(P)` 表示：从非终结符 `P` 推导出的句型中，可能出现在最右边的终结符集合。

也就是说，如果从 `P` 出发推导出的某个句型最右侧最后一个终结符是 `a`，那么：

```text
a ∈ LastVT(P)
```

### 5.2 求 LastVT(P) 的规则

对每个非终结符 `P`，按以下规则求 `LastVT(P)`：

#### 规则 1：直接出现终结符

如果有产生式：

```text
P → ... a
```

或者：

```text
P → ... a Q
```

其中 `a` 是终结符，`Q` 是非终结符，则：

```text
a ∈ LastVT(P)
```

也就是说：

- 如果产生式右部最后一个符号就是终结符 `a`，则加入；
- 如果产生式右部最后一个符号是非终结符 `Q`，倒数第二个符号是终结符 `a`，也加入。

#### 规则 2：传递加入

如果有产生式：

```text
P → ... Q
```

则：

```text
LastVT(Q) ⊆ LastVT(P)
```

即 `Q` 能够最后推出的终结符，也可能成为 `P` 最后推出的终结符。

#### 规则 3：反复迭代到不再变化

重复应用规则 1 和规则 2，直到所有非终结符的 `LastVT` 集不再增加新的终结符为止。

## 6. 本实验文法的 FirstVT / LastVT 集

对于文法：

```text
E → E + T | T
T → T * F | F
F → ( E ) | i
```

可得到：

```text
FirstVT(E) = { +, *, (, i }
FirstVT(T) = { *, (, i }
FirstVT(F) = { (, i }

LastVT(E) = { +, *, ), i }
LastVT(T) = { *, ), i }
LastVT(F) = { ), i }
```

说明：

- `E → E + T` 使 `+` 加入 `FirstVT(E)` 和 `LastVT(E)`；
- `T → T * F` 使 `*` 加入 `FirstVT(T)` 和 `LastVT(T)`；
- `F → (E)` 使 `(` 加入 `FirstVT(F)`，`)` 加入 `LastVT(F)`；
- `F → i` 使 `i` 同时加入 `FirstVT(F)` 和 `LastVT(F)`；
- 再通过 `E → T`、`T → F` 进行集合传递。

---

## 7. 算符优先关系表的生成方法

### 7.1 总体思想

算符优先关系表只记录终结符之间的关系。

表的行表示左边的终结符，列表示右边的终结符。

如果表中第 `a` 行第 `b` 列为 `<`，表示：

```text
a < b
```

如果表中第 `a` 行第 `b` 列为 `>`，表示：

```text
a > b
```

如果表中第 `a` 行第 `b` 列为 `=`，表示：

```text
a = b
```

空白表示二者之间不存在优先关系。

---

### 7.2 关系 `=` 的生成规则

如果某条产生式右部出现如下形式：

```text
... a b ...
```

其中 `a` 和 `b` 都是终结符，则：

```text
a = b
```

如果某条产生式右部出现如下形式：

```text
... a Q b ...
```

其中 `a`、`b` 是终结符，`Q` 是非终结符，则：

```text
a = b
```

在本实验文法中：

```text
F → ( E )
```

右部出现了终结符 `(` 和 `)` 中间夹着非终结符 `E`，所以：

```text
( = )
```

---

### 7.3 关系 `<` 的生成规则

如果某条产生式右部出现如下形式：

```text
... a Q ...
```

其中 `a` 是终结符，`Q` 是非终结符，则对所有：

```text
b ∈ FirstVT(Q)
```

都有：

```text
a < b
```

含义是：当终结符 `a` 后面跟着一个非终结符 `Q` 时，`Q` 内部最左边可能出现的终结符，都应该在 `a` 之后被移进。

本实验文法中的典型例子：

```text
E → E + T
```

因为 `+` 后面是非终结符 `T`，所以：

```text
+ < b,  b ∈ FirstVT(T)
```

即：

```text
+ < *
+ < (
+ < i
```

再如：

```text
T → T * F
```

因为 `*` 后面是非终结符 `F`，所以：

```text
* < (
* < i
```

再如：

```text
F → ( E )
```

因为 `(` 后面是非终结符 `E`，所以：

```text
( < +
( < *
( < (
( < i
```

---

### 7.4 关系 `>` 的生成规则

如果某条产生式右部出现如下形式：

```text
... Q a ...
```

其中 `Q` 是非终结符，`a` 是终结符，则对所有：

```text
b ∈ LastVT(Q)
```

都有：

```text
b > a
```

含义是：当非终结符 `Q` 后面跟着终结符 `a` 时，`Q` 内部最右边可能出现的终结符，遇到 `a` 时应当先归约。

本实验文法中的典型例子：

```text
E → E + T
```

因为 `E` 后面是终结符 `+`，所以：

```text
b > +,  b ∈ LastVT(E)
```

即：

```text
+ > +
* > +
) > +
i > +
```

再如：

```text
T → T * F
```

因为 `T` 后面是终结符 `*`，所以：

```text
b > *,  b ∈ LastVT(T)
```

即：

```text
* > *
) > *
i > *
```

再如：

```text
F → ( E )
```

因为 `E` 后面是终结符 `)`，所以：

```text
b > ),  b ∈ LastVT(E)
```

即：

```text
+ > )
* > )
) > )
i > )
```

---

### 7.5 与 `#` 有关的优先关系

为了进行完整的输入分析，需要加入起止符号 `#`。

通常规定：

```text
# < a    对所有可能作为表达式开头的终结符 a
b > #    对所有可能作为表达式结尾的终结符 b
# = #    表示输入结束且分析成功
```

对于本实验表达式文法：

表达式开头可能是：

```text
FirstVT(E) = { +, *, (, i }
```

但从实际表达式语法角度，合法表达式开头一般是：

```text
(, i
```

实验程序可以直接按文法机械构造，也可以结合输入合法性处理。为了保持算符优先分析表的一致性，推荐对 `#` 按开始符号 `E` 的集合处理：

```text
# < a,  a ∈ FirstVT(E)
b > #,  b ∈ LastVT(E)
# = #
```

即：

```text
# < +
# < *
# < (
# < i

+ > #
* > #
) > #
i > #

# = #
```

如果希望更贴近日常算术表达式，也可以在词法或语法入口处额外限制表达式不能以 `+` 或 `*` 开头。

根据上述规则，可得到终结符之间的优先关系表。

表中行表示栈顶终结符，列表示当前输入终结符。

|     | + | * | ( | ) | i | # |
| --- | --- | --- | --- | --- | --- | --- |
| + | > | < | < | > | < | > |
| * | > | > | < | > | < | > |
| ( | < | < | < | = | < |   |

- 本实验实现时，应将该表输出到屏幕或文件中。

## 9. 算符优先分析总控程序

### 9.1 基本思想

算符优先分析使用一个分析栈和一个输入串。

初始时：

```text
栈：#
输入：待分析表达式 + #
```

每一步比较：

```text
栈顶最近的终结符 a
当前输入终结符 b
```

根据 `a` 与 `b` 的优先关系决定动作：

```text
a < b 或 a = b ：移进
a > b          ：归约
无优先关系      ：出错
# = #          ：分析成功
```

注意：比较时不是简单比较栈顶字符，而是比较“栈中最靠近栈顶的终结符”和“当前输入符号”。因为栈顶可能是归约得到的非终结符。

---

### 9.2 移进操作

如果：

```text
a < b
```

或：

```text
a = b
```

则将当前输入符号 `b` 压入分析栈，并读取下一个输入符号。

伪代码：

```text
push(b)
read next input symbol
```

---

### 9.3 归约操作

如果：

```text
a > b
```

则说明栈内已经形成一个可以归约的短语，需要在栈中寻找最左素短语的边界。

归约时从栈顶向左扫描，寻找满足如下形式的边界：

```text
左边终结符 < 短语开头终结符
```

具体做法：

1. 从栈顶开始，找到最靠近栈顶的终结符；
2. 继续向左寻找前一个终结符；
3. 根据两个终结符之间的优先关系判断是否继续向左：
   - 如果是 `>` 或 `=`，继续向左；
   - 如果遇到 `<`，说明边界找到；
4. 将边界右侧到栈顶的符号串作为待归约短语；
5. 判断该短语是否能与某条产生式右部匹配；
6. 如果能匹配，则将该短语归约为相应非终结符；
7. 如果不能匹配，则报错。

---

## 10. 归约匹配策略

算符优先分析中，归约时可以忽略非终结符名称上的差异，重点检查右部结构是否能匹配某条产生式右部。

例如文法中有：

```text
E → E + T
```

在栈中可能找到的短语形态为：

```text
F + F
```

虽然文法中没有产生式 `E → F + F`，但由于非终结符在算符优先分析中通常只作为“属性占位符”，可以把非终结符统一看作 `N` 来匹配结构。

因此可以把产生式右部抽象为模式：

```text
E + T  → N + N
T * F  → N * N
( E )  → ( N )
i      → i
T      → N
F      → N
```

实际实现时，推荐使用如下归约模式：

| 待归约短语模式 | 可归约为 |
| --- | --- |
| `i` | `N` |
| `N + N` | `N` |
| `N * N` | `N` |
| `( N )` | `N` |

其中 `N` 表示任意非终结符占位符。

这种做法符合课本中“算符优先分析不关心非终结符具体名字，只关心终结符优先关系和短语结构”的处理方式。

## 11. 分析成功条件

当满足以下条件时，分析成功：

```text
当前输入符号为 #
栈中内容为 #N
```

或者用课本伪代码中的形式表示：

```text
a 是 #，且栈顶位置为 2
```

也就是：

```text
栈底为 #
栈中只剩一个归约后的非终结符
输入也读到 #
```

此时可以输出：

```text
分析成功 / 表达式正确
```

## 12. 出错条件

程序应至少识别以下错误情况：

1. 当前输入字符不是合法终结符；
2. 当前栈顶终结符与输入终结符之间没有优先关系；
3. 归约时找不到左边界；
4. 找到的待归约短语不能匹配任何产生式右部模式；
5. 输入结束后栈中没有归约成单一表达式；
6. 括号不匹配；
7. 运算符位置错误，例如：

```text
i+i)*i
```

或：

```text
i+i+(*i)
```

## 14. 推荐实现流程

### 14.1 数据结构

推荐使用以下数据结构：

```text
productions        存储文法产生式
nonTerminals       存储非终结符集合
terminals          存储终结符集合
firstVT            存储每个非终结符的 FirstVT 集
lastVT             存储每个非终结符的 LastVT 集
priorityTable      存储终结符之间的优先关系
analysisStack      分析栈
inputString        输入串
```

优先关系表可以使用二维数组或映射：

```text
table[a][b] = '<' / '=' / '>' / 空
```

---

### 14.2 程序主流程

```text
1. 初始化文法产生式
2. 初始化终结符集合和非终结符集合
3. 求 FirstVT 集
4. 求 LastVT 集
5. 构造算符优先关系表
6. 输出 FirstVT / LastVT 集和优先关系表
7. 读取输入表达式
8. 在表达式末尾添加 #
9. 初始化分析栈，压入 #
10. 执行算符优先分析
11. 输出每一步分析过程
12. 输出最终判断结果
```

## 15. 算符优先分析伪代码

```text
stack = ['#']
input = expression + '#'
ip = 0

while true:
    b = input[ip]
    a = topMostTerminal(stack)

    if a == '#' and b == '#' and stack == ['#', 'N']:
        accept
        break

    relation = priorityTable[a][b]

    if relation is empty:
        error
        break

    if relation == '<' or relation == '=':
        push b into stack
        ip = ip + 1
        output 移进

    else if relation == '>':
        phrase = findHandle(stack)
        if phrase matches one reduction pattern:
            replace phrase by N
            output 归约
        else:
            error
            break
```

其中：

```text
topMostTerminal(stack)
```

表示从栈顶向下寻找最近的终结符。

```text
findHandle(stack)
```

表示从栈顶向左寻找最左素短语边界。

---

## 16. findHandle 的核心逻辑

归约时，不能简单弹出一个符号，而要找到整个待归约短语。

伪代码如下：

```text
function findHandle(stack):
    right = stack.top

    k = index of topMostTerminal(stack)

    while true:
        j = index of terminal immediately before k, skipping nonterminals
        relation = priorityTable[stack[j]][stack[k]]

        if relation == '<':
            left = j + 1
            return stack[left ... right]

        else if relation == '=' or relation == '>':
            k = j
            continue

        else:
            error
```

其中需要注意：

- 扫描边界时比较的是终结符之间的优先关系；
- 非终结符可以跳过；
- 找到 `<` 后，`<` 右侧到栈顶就是待归约短语。

## 19. 给 agent 的实现要求摘要

需要实现的是“基于优先关系表的算符优先分析器”，不是“优先函数分析器”。

具体要求：

1. 使用文法：

```text
E → E + T | T
T → T * F | F
F → ( E ) | i
```

2. 自动求 `FirstVT` 和 `LastVT` 集；
3. 根据文法规则自动构造算符优先关系表；
4. 输出优先关系表；
5. 使用 `#` 作为输入结束符和栈底符号；
6. 通过算符优先关系执行移进和归约；
7. 归约时寻找最左素短语；
8. 归约匹配时可以将非终结符统一视为 `N`；
9. 输出每一步分析栈、剩余输入、优先关系和动作；
10. 判断输入表达式是否合法；
11. 至少测试 `(i+i)*i` 和 `i+i)*i`；
12. 不需要实现 Floyd 优先函数方法。
