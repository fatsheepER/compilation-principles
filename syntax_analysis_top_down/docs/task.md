# 实验二：预测分析语法分析器

## 一、实验目的和要求

1. 用预测分析技术实现语法分析器。
2. 理解自顶向下语法分析方法。
3. 熟练掌握预测分析程序的构造方法。

---

## 二、实验内容

### 1. 原始文法

算术表达式的文法为 **G[E]**：

```text
E → E + T | T
T → T * F | F
F → (E) | i
```

### 2. 实验任务

使用预测分析法，按照文法 **G[E]** 对算术表达式进行语法分析，判断表达式是否正确。

表达式包括：

- 加法运算符：`+`
- 乘法运算符：`*`
- 括号：`(`、`)`
- 操作数：单个无符号整数或 `i`

---

## 三、实验步骤

1. 阅读课本相关章节，将上述算术表达式文法改造成 **LL(1) 文法**。
   - 消除左递归
   - 必要时提取左公因子
2. 设计预测分析表。
3. 按照教材第 63 页图 4.4 中的算法编写预测分析程序。
4. 上机调试程序。
5. 发现错误后，分析错误原因，并修改完善程序。

---

## 四、测试要求

1. 为降低难度，表达式中不含变量，只含：
   - 单个无符号整数
   - 或符号 `i`
2. 如果遇到错误表达式，应输出错误提示信息。
   - 错误提示越详细越好。
3. 测试表达式建议事先放在文本文件中。
   - 一行存放一个表达式
   - 每个表达式以分号 `;` 结束
4. 语法分析程序的输出结果写入另一个文本文件中。
5. 选作功能：
   - 当判断表达式正确时，输出计算结果。

---

## 五、与词法分析阶段的接口约定

由于本项目计划让语法分析阶段复用词法分析阶段的输出，语法分析程序不再直接从原始字符串逐字符扫描，而是读取词法分析产生的 token 流。

### 1. 输入文件

语法分析程序建议读取：

- `lexical_analysis/output/result.txt`：词法分析成功后产生的 token 流。
- `lexical_analysis/output/error.txt`：词法分析错误信息。

如果 `error.txt` 非空，说明输入源程序存在词法错误，语法分析阶段应先报告“词法分析未通过”，不继续进行预测分析。

### 2. token 文件格式

当前词法分析结果每行一个 token，格式如下：

```text
(lexeme, token_code)
```

例如表达式 `1+2;` 的 token 流为：

```text
(1, 1)
(+, 200)
(2, 1)
(;, 301)
```

其中 `token_code` 与 `lexical_analysis/src/token.h` 中的 `TokenType` 保持一致。

### 3. 语法分析终结符映射

预测分析表只关心表达式文法中的终结符，因此需要将词法 token 归一化：

| 词法 token             | 种别码 | 语法分析终结符 |
| -------------------- | --- | ------- |
| `TK_IDENTIFIER`，且 lexeme 为 `i` | 0   | `i`     |
| `TK_INT_LITERAL`     | 1   | `i`     |
| `OP_PLUS`            | 200 | `+`     |
| `OP_MUL`             | 202 | `*`     |
| `SEP_LPAREN`         | 302 | `(`     |
| `SEP_RPAREN`         | 303 | `)`     |
| `SEP_SEMICOLON`      | 301 | `#`     |

其中 `;` 表示一个表达式结束，进入预测分析程序前可转换为输入结束符 `#`。

除上表外的 token，如其他标识符、`-`、`/`、关键字、赋值号、关系运算符、字符常量、字符串常量等，均不属于本实验给定文法，应作为语法错误处理。

### 4. 多表达式输入

如果一个 token 文件中包含多条表达式，可以按 `SEP_SEMICOLON` 切分为多段，分别进行预测分析。每段表达式分析时，在末尾补入 `#`。

## 八、实验指导

### 1. 改造后的 LL(1) 文法

将原文法 **G[E]** 改造为 **G’[E]**：

```text
E  → T E'
E' → + T E' | ε
T  → F T'
T' → * F T' | ε
F  → ( E ) | i
```

### 2. 文法说明

原始文法中存在直接左递归：

```text
E → E + T | T
T → T * F | F
```

改造后：

- `E` 表示一个完整表达式。
- `E'` 表示表达式后续可能出现的 `+ T` 部分。
- `T` 表示一个项。
- `T'` 表示项后续可能出现的 `* F` 部分。
- `F` 表示因子，可以是括号表达式，也可以是操作数 `i`。

---

## 九、可整理到报告中的关键内容

### 1. 预测分析程序基本思想

预测分析程序使用一个分析栈和一个输入串进行匹配。

基本过程如下：

1. 将 `#` 和开始符号 `E` 压入分析栈。
2. 从输入串读取第一个符号作为当前输入符号。
3. 弹出栈顶符号 `X`。
4. 根据 `X` 的类型进行处理：
   - 如果 `X` 是终结符，则判断它是否与当前输入符号匹配。
   - 如果 `X` 是非终结符，则查预测分析表 `M[X, a]`。
   - 如果 `X` 是 `#`，则判断输入是否也结束。
5. 如果查表得到产生式，则将产生式右部逆序压入分析栈。
6. 重复上述过程，直到分析成功或发现错误。

---

### 2. 推荐的程序输入设计

输入文件示例：

```text
1;
i+i;
(i+i)*i;
((i+i)*i+i;
i+i+i+(*i);
```

实际实现时，该文件应先交给词法分析程序处理，语法分析程序读取词法分析生成的 token 流。

---

### 3. 推荐的程序输出设计

输出文件示例：

```text
1;                正确
i+i;              正确
(i+i)*i;          正确
((i+i)*i+i;       错误：缺少右括号
i+i+i+(*i);       错误：运算符后不能直接出现 *
```

---

## 十、实现时需要注意的问题

1. 输入表达式以分号 `;` 结束，但预测分析程序内部通常可以将分号转换为结束符 `#`。
2. 语法分析阶段读取词法 token 流，不再重复实现字符级扫描。
3. 整数常量和 lexeme 为 `i` 的标识符 token 需要统一转换为文法终结符 `i`。
4. 当前文法只支持 `+` 和 `*`，遇到 `-`、`/` 等其他运算符应报语法错误。
5. 空产生式 `ε` 不需要压入分析栈。
6. 产生式右部入栈时必须逆序压入。
7. 如果后续需要输出更精确的行号和列号，建议让词法分析输出文件保留位置信息，或让语法分析程序直接链接 `lexical_analysis_lib` 获取完整 token 数据。

---

## 十一、建议完成顺序

1. 准备表达式测试文件，每行一个以 `;` 结束的表达式。
2. 运行词法分析程序，生成 `result.txt` 和 `error.txt`。
3. 在语法分析程序中读取并解析 `result.txt`。
4. 如果 `error.txt` 非空，输出词法错误并停止语法分析。
5. 将词法 token 归一化为 `i`、`+`、`*`、`(`、`)`、`#`。
6. 按分号切分多条表达式。
7. 构造 LL(1) 文法和预测分析表。
8. 用栈实现预测分析算法。
9. 输出每个表达式的分析结果。
10. 增加详细错误提示。
11. 选做：在语法正确时计算表达式结果。
